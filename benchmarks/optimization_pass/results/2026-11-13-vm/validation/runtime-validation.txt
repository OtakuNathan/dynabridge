Confirmed Python reference reset defect and fix (final update)
===========================================================

No code or test edits followed these timestamps.

The baseline decremented the old pointer before retaining a borrowed replacement
or publishing it. Two independently checkable failures were reproduced:
1. reset(ref.get()) with the only owning ref: AddressSanitizer heap-use-after-free
   in Py_INCREF, baseline python.h:58, after Py_XDECREF at line 55 freed the object.
2. The old object's custom deallocator read owner.get() while replacing it with
   Py_None: it observed the old pointer, not the new one (deterministic exit 2).

The corrected implementation retains borrowed input first, publishes it with
std::exchange, and only then decrements the previous pointer. The adopted/owned
policy still requires an independently owned incoming reference, even when the
pointer equals the old pointer. A finalizer's reentrant reset remains published
after the outer reset returns.
